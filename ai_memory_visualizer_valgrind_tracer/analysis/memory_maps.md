Based on my analysis of the programs running I have determined that a core difference between the "stack" and "heap" is that the stack will start storing memory on the highest address it can access and write down into earlier addresses. This is what I learned from running the stack_example.c program especially. After discovering this I asked my demonstrator on site if this was the case and he agreed. Furthermore when writing to the "heap", the machine will start on the lowest address it can access safely and begin allocating into higher addresses. I believe this is so memory is not easily overlapped and a machine can easily diagnose whether it has reached it's memory limit.
Upon running the aliasing_example program I quickly realised that it has 2 pointers both poitning to the same piece of allocated memory. The program then uses the 'a' to free the memory but continues to use the 'b' to access the now freed memory, resulting in dangling pointers and a use after free.
Following my analysis of the 2 programs, I requested AI to build me a memory diagram based on the 2 outputs of the programs. The diagram correctly put what I was imaginging into a diagram further cementing that my original hypothesis is correct. Although the AI said that the stack starting high and digging into lower addresses for memory was machine specific but I could not find any examples of other machines doing anything differently.
The stack_example, as the name suggests, is an example of memory being placed onto the stack. The aliasing_example program was placing the memory on the heap and passing the address to 2 pointers. I believe the 2 pointers are not responsible for for freeing the the memory, but the arr should be freed first and then remove the use after free.
